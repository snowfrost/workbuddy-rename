# 空间卫生标准与季度深检

> 方法论出处：融合自 **马厩管理法（majiu-management，MIT © 2026 majiabin2020）** 的
> 「草稿三分法」「非破坏性铁律」「季度巡检」，按 workbuddy-rename 的跨空间场景改写。
> 原始仓库：https://github.com/majiabin2020/majiu-management
>
> **注意**：马厩法本身**不含**路径引用修复能力，其「梳理优化」只做到移动 + 备份 + 回收站。
> 在 WorkBuddy 里移动工作空间，必须回到 SKILL.md 第 4/4.5/4.6 节修 `sessions.cwd`、`projects/` 目录名与产物索引，
> 否则会「点开空白 / 产物打不开」。

## 一、空间内部结构与三分法映射

空间内部四件套与草稿三分法的对应关系：

| 目录 | 装什么 | 对应三分法 | 处置 |
|---|---|---|---|
| `01_outputs/` | 交付物（再分 images/docs/video/html） | 资产型 | **必须保留** |
| `02_assets/` | 素材（原始输入、参考图、外部下载） | 资产型 | **必须保留** |
| `03_scripts/` | 脚本、可复用代码 | 配方型 | 可清，但须先写重生成指引 |
| `04_temp/` | 中间产物（中间 HTML、临时日志、抽帧、试跑输出） | 配方型 / 依赖型 | 按下面判据分流 |

## 二、草稿三分法（`04_temp/` 的清理判据）

清 `04_temp/` 前，**逐个文件**判断属于哪一类：

| 类别 | 判断标准 | 处置 |
|---|---|---|
| **配方型** | 文字类草稿：脚本、中间 HTML、Markdown 中间稿（KB 级） | 可清理，但**必须先在记忆里登记「重生成指引」**；体积小（合计 <1MB）时也可直接留着 |
| **资产型** | AI 生成的图片/视频/3D 源文件、人工改过的稿、当天抓取的数据、OCR 结果等不可复现或重生成不划算的 | **必须保留**，移入 `02_assets/`，大文件先 zip |
| **依赖型** | `node_modules`、`venv`、`.venv` 等可由清单文件重装的 | 可直接删（`os.remove` 逐文件 / `rmdir` 空壳，见 SKILL.md 坑列表），**先确认 `package.json` / `requirements.txt` 存在** |

**原则：记忆存配方，磁盘存资产。**
文字草稿可以重生成，真正不可复现的是媒体资产和当天的数据 —— 省 token 和省硬盘不必二选一。

### 重生成指引模板（写进 `.workbuddy/memory/MEMORY.md`）

清理配方型草稿前，在记忆里留一条可复现的记录：

```markdown
## 重生成指引：<产物名>
- 输入来源：<原始素材路径 / 数据出处>
- 执行命令：<完整命令，含解释器绝对路径>
- 关键参数：<模型、尺寸、种子、页数等>
- 产出位置：<预期落盘路径>
- 备注：<依赖的 venv / 已装的包 / 坑>
```

## 三、非破坏性铁律（量化条款）

任何处置动作，永远按这个顺序：

1. **备份先行**：复制到 `<空间>/.workbuddy/backups/<YYYY-MM-DD>/`，确认备份成功再动手。
2. **小批量**：每批最多 **10 个文件**，每批完成后核对一次。
3. **回收站优先**：优先走系统回收站，不用 `rm` / `Remove-Item -Force`。
   - Windows 本机注意：本 skill 的沙箱把删除包装成回收站操作，失败时 fail-closed（见 SKILL.md 坑列表）。
   - 确需真删的临时文件，用 Python `os.remove` 逐文件删（**文件能删、目录壳删不掉**），并用 Windows 原生绝对路径。
4. **出错即停**：任一批出现失败，立即停止，不继续下一批、不重试同一个锁定的目录。
5. **拍板权在人**：超过 50 个文件的批量删除会触发 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 配额，必须拆轮次并先取得确认。

## 四、季度只读深检

与每日 9:30 的「归档」自动化互补：**归档是写操作（搬家+修链路），深检是纯只读（出报告等拍板）**。

### 安全铁律（优先级最高）

1. 深检全程**只读**：不移动、不重命名、不删除任何文件。
2. 报告产出后**停下等拍板**，没有明确同意不执行任何处置。
3. 处置阶段回到上面的「非破坏性铁律」。

### 步骤

1. **磁盘占用分析**：跑 `scan_workspaces.py --out scan.json` 得各空间体积与文件数；再对空间大户下钻，列出 >10MB 的单个文件。
2. **冷文件检查**：找出长期未修改（>90 天）且未被任何会话、记忆引用的目录/文件。
3. **烂尾任务核对**：对照 `_总索引.md` 的待办栏与 `sessions` 表 —— 有没有长期未动、状态悬空的任务？
4. **记忆健康**：`.workbuddy/memory/` 有无超 30 天未蒸馏的日志；`MEMORY.md` 是否超限或有互相矛盾的条目。
5. **产出报告**：按下方模板生成，存到 `<空间>/.workbuddy/inspections/YYYY-MM-DD-巡检报告.md`，对话中给"先结论后明细"的摘要。
   每条建议必须标注分类（归档压缩 / 外移 / 进回收站 / 无需处理），并显式声明「等待拍板，未拍板不执行」。

### 报告模板

```markdown
# 空间巡检报告 YYYY-MM-DD

## 结论（一句话）
例：D:\WorkBuddy 总计 X GB，96% 来自 A/B/C 三个空间；文字草稿合计不足 10MB 不构成问题。

## 一、磁盘大户 TOP5
| 空间/条目 | 体积 | 性质判断（资产型/配方型/依赖型） | 建议 |

## 二、冷文件候选（>90 天未引用）
| 路径 | 大小 | 最后修改 | 建议 |

## 三、任务水位异常
- 长期未动、状态悬空的任务：…（无则写"无"）
- 根目录散装文件 / 无主目录：…（无则写"无"）

## 四、记忆健康
- 待蒸馏日志：…（无则写"无"）
- MEMORY.md 字符数 / 冲突条目：…

## 处置方案（供拍板）
- 方案 A：…
- 方案 B：…

> 本报告为只读巡检结果，未对任何文件做改动。请拍板后执行。
```

### 巡检自动化指令模板（需用户拍板后才创建）

scheduleType `recurring`，每年 1/4/7/10 月 1 日 09:00 执行（RRULE `FREQ=YEARLY;BYMONTH=1,4,7,10;BYMONTHDAY=1;BYHOUR=9;BYMINUTE=0`）。

prompt 模板（必须自包含，未来会话看不到当前对话）：

```
对 D:\WorkBuddy 执行工作空间季度只读巡检。步骤：
1. 加载 workbuddy-rename skill，按其 references/space-hygiene.md 的「季度只读深检」规程执行。
2. 巡检为纯只读扫描，禁止移动、重命名、删除任何文件。
3. 按报告模板产出巡检报告，保存到 D:\WorkBuddy\skill\.workbuddy\inspections\，并在对话中给出"先结论后明细"的摘要。
4. 报告完成后即停止，等待用户拍板。未经用户明确同意，不执行任何处置动作。
```

## 五、任务水位（可选，空间多到需要台账时）

workbuddy-rename 的主台账是 `_总索引.md`（记录位置）。若某段时间任务烂尾严重、想要更强的状态机，
可在 `_总索引.md` 的「待办」栏之外，为**单个繁忙空间**增设一份 `_台账.md`：

| # | 任务名 | 状态 | 开始 | 结束 | 产出位置 | 备注 |
|---|---|---|---|---|---|---|
| 1 | … | 在厩 / 出栏 | YYYY-MM-DD | YYYY-MM-DD | … | 烂尾重启等情况 |

- 状态：`空栏`（无进行中任务）/ `在厩`（进行中）/ `出栏`（已完成，终态）
- 同一空间**同时最多一匹「在厩」**；开新任务前若有「在厩」未结束，先问用户是否收尾旧任务
- 状态变更**即时写入**，不允许"先干活后补账"
- 出栏任务的产物路径、经验条目位置必须能从索引一眼找到 —— **找不到等于没归档**
